# Quran tajweed data

- Source: Quran Foundation Content API v4
- Endpoint: `https://api.quran.com/api/v4/quran/verses/uthmani_tajweed`
- Field: `text_uthmani_tajweed`
- Narration: Hafs an Asim
- Expected coverage: 114 surahs and 6,236 ayahs

The bundled JSON is generated by `scripts/prepare-quran-tajweed.cjs`. The
generator validates every surah/ayah key, removes the source verse-number
marker (Iqro renders its own marker), escapes text, and only converts tajweed
annotations into local `tajweed-*` span classes.

For Android WebView, every tajweed boundary is aligned to a complete Unicode
grapheme cluster. A base Arabic letter and all of its attached harakat are
therefore always emitted inside one text/span run. This prevents a combining
mark from being rendered on a dotted circle, across mad and every other
tajweed rule. If several source annotations touch one cluster, the rule on the
base letter wins; otherwise the first annotated rule colors the complete
cluster. The Arabic characters and their order are not changed.

The generated metadata records how many source boundaries were repaired. The
generator also compares the visible text before and after rendering for every
ayah, so generation stops if a Quran character is added, removed, or reordered.

The API payload also contains 1,561 legacy U+0672 characters. This code point
is used there as a visual stand-in for dagger alif, but the Android/KFGQPC font
renders it as a circular symbol. The generator converts these occurrences to
canonical U+0670 before grapheme alignment. The single U+0672 + combining-hamza
sequence at Al-Baqarah 2:72 is converted to U+0670 + the separate hamza letter,
matching the local KFGQPC reference. Generation requires exactly 9,726 final
U+0670 characters and fails if these integrity counts change.

https://api-docs.quran.foundation/docs/content_apis_versioned/4.0.0/quran-verses-uthmani-tajweed/
